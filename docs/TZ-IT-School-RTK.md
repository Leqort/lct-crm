## 2. Актуальность задачи

В соответствии с реализацией поручений Правительства РФ по развитию кадрового потенциала в сфере информационных технологий, а также во исполнение задач, поставленных в рамках федеральных проектов, в настоящее время ведётся работа по формированию системы контроля за подготовкой квалифицированных ИТ-специалистов среди студентов вузов и обучающихся школ.

Для объективного ранжирования образовательных программ по ИТ-направлениям необходимо создать систему по контролю за подготовкой кадрового резерва по ИТ-направлениям. **Ранжирование происходит на основе востребованности программы**, которое становится очевидным по статистическим данным:

- заявки на обучение;
- количество обучающихся;
- количество параллельных потоков.

Данная система (далее — **CRM**) позволит контролировать взаимодействие с учебными заведениями для приобретения навыков работы с востребованными на рынке цифровыми инструментами. На их основе обучающиеся смогут получить актуальные компетенции по различным ИТ-направлениям. Решение автоматизирует процесс взаимодействия с каждым вузом по разным образовательным программам, что позволит учебным заведениям получать конечный результат быстрее.

## 3. Описание задачи

Разработать систему контроля взаимодействия с учебными заведениями для приобретения навыков работы с востребованными на рынке цифровыми инструментами.

Система позволит:

- визуализировать цикл взаимодействия с каждым вузом;
- контролировать путь жизненного цикла каждого взаимодействия с вузом по всем ИТ-программам и ИТ-продуктам.

**Задача сервиса** — сокращение трудозатрат сотрудников ИТ Школы РТК на взаимодействие с вузами за счёт автоматизации всего пути взаимодействия.

## 4. Требования к сервису

В рамках данной задачи предполагается реализовать **CRM-систему**, которая:

- автоматизирует процесс взаимодействия с вузом;
- имеет возможность интеграции по API со сторонними системами заказчика в виде **LMS** и **сайтом**;
- соответствует требованиям безопасности **152-ФЗ** «О персональных данных» и **приказу ФСТЭК № 117**.

### 4.1. Общие требования к сервису

| `SRV-02` | Формировать **отчёты** по всем существующим взаимодействиям с вузами за **выбранный период**. |

### 5.1. Ролевая модель — `FR-12`

| Роль | ID | Права по ТЗ |
|---|---|---|
| **Пользователь** | `ROLE-USER` | Работа в интерфейсе программы с допустимыми в рамках прав данными после прохождения авторизации. |
| **Руководитель** | `ROLE-LEAD` | Работа в интерфейсе программы с допустимыми в рамках прав данными после прохождения авторизации; **привилегии выше, чем у пользователя**; имеет возможность **изменять ответственных пользователей за вузы (менять, удалять, назначать)**. |
| **Администратор** | `ROLE-ADMIN` | Расширенные права для реализации дополнительных настроек и управления правами пользователей, а также **разграничение пользователей по доступу к данным**. |

Соответствие ролей целевой аудитории (раздел 7):

- `ROLE-USER` — КАМ (key account manager) = менеджеры по вузам (**около 20**);
- `ROLE-LEAD` — руководители менеджеров по вузам;
- `ROLE-ADMIN` — технические специалисты ИТ Школы РТК.

### 7.2. Администратор сервиса должен иметь возможность

| ID | Возможность |
|---|---|
| `UC-A-01` | Управлять правами пользователей, дополнительными настройками и ограничениями пользователей по видимой информации, дополнять и корректировать их. |

### 7.3. Возможный пользовательский путь — `UX-PATH`

1. Пользователь попал на **окно авторизации** в систему.
2. Пользователь **авторизовался** и получил доступ к тем данным, доступ к которым у него есть.
3. Предусмотрена **фильтрация данных** по вузам, ИТ-программам, ИТ-продуктам и статусу взаимодействия по ним.
4. Возможна **актуализация статуса** по текущему вузу, программе, продукту — с проставлением комментария, добавлением файлов и, если необходимо, с корректировкой статуса workflow.
5. Возможны **создание и выгрузка отчёта** за выбранный период, ответственным, ИТ-программам, ИТ-продуктам.

**Целевая аудитория** — сотрудники ИТ Школы РТК.
